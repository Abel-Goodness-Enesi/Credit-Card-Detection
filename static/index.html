How it works and what it cannot do

This is a small feed forward neural network. A transaction is 30 numbers: Time, Amount, and 28 anonymised components (V1 to V28) produced by PCA. They cannot be read as real world fields such as merchant or location. The numbers enter the first layer of nodes on the left. Each node multiplies its inputs by learned weights, adds a bias and passes the result through a nonlinear function. The last node outputs a probability of fraud.

A transaction is flagged when that probability is at or above the threshold. The threshold was chosen on a validation set to favour catching fraud over avoiding false alarms. The brightness of each node shows how strongly it fired for this input. That shows the computation, not a human readable reason for the decision.

What the demo stream is

Every transaction shown comes from the held out test set, which the network never trained on. The pool is shuffled and contains far more fraud than real card traffic, where fraud is well under 1 percent, so the tallies above are not real world rates. The honest figures are in the model card line.

Limits

Trained on one public dataset of European card transactions from 2013 with very few fraud cases. The test figures come from about 98 frauds, so they can move by several points. About one in three alerts is a false alarm. Only logistic regression and untuned gradient boosting were compared against it. This is a learning project and must not be used for real payment decisions.
